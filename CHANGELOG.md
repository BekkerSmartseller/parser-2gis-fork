# История изменений

## [2.6.5] - 2026-08-16

### Оптимизация парсинга (файловый режим)

- **Пропуск полностью собранных сетей**: если из выдачи уже собрано
  `org.branch_count` филиалов сети (org.id == network_id в `/branches/{id}`),
  заход на страницу филиалов не выполняется — минуты экономии на больших
  задачах.
- **Дедуп сетей по network_id** (раньше одна сеть обрабатывалась дважды —
  URL с городом и без).
- **Быстрая загрузка страниц филиалов**: вместо ожидания всех XHR — короткая
  пауза (~1 с), карточки филиалов SSR-ятся сразу.
- **Быстрый дренаж byid** после клика: окно 3 с → 1.5 с.
- **Межзадачный дедуп `seen_firms`** (опция `skip_seen_firms`, по умолчанию
  выкл): кэш собранных фирм в `user_path/seen_firms.txt`, повторные задачи
  пропускают уже виденные организации. CLI `--parser.skip-seen-firms`,
  web `advanced.skip_seen_firms`.
- **Монитор вкладки**: интервал health-check `GET /json` 5 с → 15 с
  (меньше шума в логе).

## [2.6.4] - 2026-08-15

### Устойчивость к «зависшим» запросам 2GIS

- `_wait_requests_finished` больше не роняет задачу `TimeoutError`, если XHR
  к 2GIS завис (счётчик `window.openHTTPs` не обнуляется): по таймауту (120с)
  логируем предупреждение, сбрасываем счётчик и продолжаем парсинг.
- Раньше зависший запрос убивал всю задачу (status=error) посреди работы.

## [2.6.3] - 2026-08-15

### Диагностика пустой страницы филиалов

- Если страница `/branches/{id}` не содержит карточек филиалов (сеть с одним
  филиалом или невалидный/удалённый id), парсер пробует вернуть саму
  организацию через фирм-страницу (`/firm/{id}`), а при недоступности даёт
  явный лог: «организация {id} не найдена в 2GIS».
- Несуществующие организации 2GIS редиректит на «город по умолчанию» — это
  не признак другого города, а пустое состояние для неизвестного id.

## [2.6.2] - 2026-08-15

### Веб-сайты: массив внутри contacts

- Все сайты организации теперь лежат в `contacts['websites']` (массив) рядом с
  одиночным `contacts['website']` (первый сайт — для совместимости), а не
  отдельным полем записи.
- CSV/XLSX «Веб-сайты (все)» и HTML-кнопки «Сайт/Сайт 2/...» читают данные
  из `contacts['websites']`.

## [2.6.1] - 2026-08-15

### Все веб-сайты организации

- Если у организации несколько сайтов, теперь собираются **все** (массив `websites`),
  а не только первый; `contacts.website` сохранён для совместимости (первый сайт).
- CSV/XLSX: новая колонка «Веб-сайты (все)» (сайты через разделитель), HTML: кнопки
  «Сайт», «Сайт 2», … для всех сайтов.
- query-параметры (utm и т.п.) у сайтов отрезаются, дубли схлопываются.

## [2.6.0] - 2026-08-15

### Сбор всех филиалов сетей

- Парсер собирает **все филиалы** сети: когда сеть в выдаче показана одной
  карточкой (например при рубричном поиске), он открывает страницу
  `/branches/{network_id}` (ссылка «N филиала») и добирает остальные филиалы;
  дедуп по id — филиалы из выдачи повторно не собираются.
- Входные ссылки `/branches/{id}` и `/branches/{id}/firm/{firm}/...` парсятся
  напрямую (страница списка филиалов и конкретная фирма внутри сети).
- Опция `parser.collect_branches` (по умолчанию включена), CLI
  `--parser.collect-branches {yes,no}`, web API: `advanced.collect_branches`.
- Фильтрация byid-ответов по id-префиксу карточки — «похожие» организации
  в результат не попадают.

## [2.5.0] - 2026-08-14

### Геокодинг и маршруты через 2GIS (для интеграций)

- **Геокодинг адреса** — `POST /api/geocode`:
  - новый UI 2GIS шлёт поиск через `catalog.api.2gis.ru/3.0/markers/clustered` (а не
    `items/search`) — геокодер перехватывает этот ответ;
  - выбор наилучшего результата по релевантности (организации предпочтительнее дорог/районов);
  - возвращает `{lat, lon, name, address, id}` — `id` нужен для точной привязки точек маршрута;
  - жёсткий дедлайн вместо бесконечного ожидания ответа.
- **Маршруты** — `POST /api/route`:
  - 2GIS больше не отдаёт маршруты через `routing.api.2gis.ru` / `public-transport.api.2gis.ru`
    (эндпоинты мертвы) — итинерарий рендерится **на сервере (SSR)** и парсится из DOM;
  - режимы: авто/ОТ/пешком/вело (табы `tab/car|bus|pedestrian|bike`);
  - точки `lon,lat;ID` (ID из `/api/geocode`) — точная привязка к объекту;
  - ответ содержит `duration_s`, `segments` (walk/bus/trolleybus/tram/shuttle_bus/...),
    `variants` — все предложенные 2GIS варианты;
  - **метро** (Москва/СПб и др.): тип `metro`, номер линии из карточки;
  - анти-бот проверка детектируется и ретраится.

### Исправления

- `POST /api/cities` без `code` больше не падает с `NameError` (`_translit_slug` восстановлен);
- прокси с авторизацией в `--proxy-server` больше не ломает Chrome
  (`ERR_NO_SUPPORTED_PROXIES`) — такой прокси пропускается, Chrome идёт напрямую;
- геокодер не зависал при отсутствии `items/search` в новом UI;
- убран циклический `variants` в ответе маршрута (`Circular reference detected` при
  json-сериализации);
- удалена утечка очереди перехваченных ответов (`_ANY_2GIS_PATTERN`);
- починен `__repr__` в `MainParser`.


## [2.4.0] - 2026-08-13

### Надёжный город + серверный режим + толерантность к данным

- **Умное определение города (fallback-цепочка):** город филиала больше не берётся
  только из `adm_div.type == 'city'`. Добавлена цепочка из нескольких источников:
  1. явный город;
  2. регион федерального значения (Москва / Санкт-Петербург / Севастополь);
  3. город-центр муниципального округа (`district_area` → город, например
     «Гурьевский муниципальный округ» → «Гурьевск», словарь ~100 районов);
  4. населённый пункт (`settlement`) с очисткой префикса (`пос.`, `пгт`, `г.`, `с.`, `д.`);
  5. регион как последний запасной вариант.
  Благодаря этому организации, у которых 2GIS не указывает город (посёлки, городские
  округа, ЗАТО), больше не теряют город в выходных данных.
- **Толерантность к битым контактам:** `Contact.type`/`value` стали необязательными
  (по умолчанию пустые), а `ContactGroup.contacts` — списком по умолчанию. Контакты,
  пришедшие одним объектом вместо списка, автоматически приводятся к списку.
  Одна аномальная контактная группа больше не роняет всю запись.
- **Серверный режим веб-интерфейса:**
  - `--web-host` — адрес, на котором слушает веб-сервер (по умолчанию `127.0.0.1`);
  - `--web-no-browser` — не открывать браузер автоматически (для запуска на сервере/в Docker).
- **Генератор ссылок:** в данные `/api/generator` добавлено поле `group` — имя
  верхнеуровневой рубрики-группы для каждого пункта рубрикатора (удобно группировать
  при выборе).


## [2.3.0] - 2026-08-13

### Координатный поиск + надёжность + расширенный справочник

- **Координатный (пространственный) поиск:** парсер принимает URL без городского
  префикса с параметром `?m=lon,lat/zoom` (например `https://2gis.ru/search/фитнес клуб?m=45.51,58.37/12`).
  2GIS ищет по кругу вокруг точки, расширяя охват за пределы одного города
  («в Шарье и области»). См. раздел README «📍 Координатный (пространственный) поиск».
- **404 «Точных совпадений нет»:** добавлен ретрай без рубрики (`/rubricId/` убран),
  если ретрай успешен — парсинг продолжается; исправлено чтение устаревшего ответа
  (буфер ответов сбрасывается перед ретраем, выбирается актуальный HTML-документ).
- **Расширение справочника городов:** эндпоинты `POST /api/cities` и `GET /api/cities`
  для добавления отсутствующих городов (транслит-slug код, сохраняются в
  `~/.local/share/parser-2gis/cities_custom.json`, попадают в `/api/generator`).
- **Записи:** в извлечённые записи добавлены координаты (`point_lat`/`point_lon`)
  и расписание работы (JSONB `{days, comment, ...}`).
- **Chrome/прокси:** без явного прокси Chrome запускается с `--no-proxy-server`
  (иначе невалидный `ALL_PROXY`/socks:// давал `ERR_SOCKS_CONNECTION_FAILED`);
  CDP-вызовы идут с `trust_env=False`.
- **Очистка:** удалён лишний скрипт-обёртка `parser-2gis.py`.


## [2.2.0] - 2026-08-11

### Конкурентный парсинг + прокси

- Пул задач (JobManager): несколько парсингов одновременно, лимит `max_concurrent`, очередь, каждый job возвращает `job_id` (статус/результаты/скачивание по id, новые эндпоинты `/api/jobs`).
- Задачи сверх лимита `max_concurrent` встают в очередь и выполняются по мере освобождения Chrome.


## [2.1.0] - 2026-08-11

### Веб-интерфейс: переход с Flask на Litestar

- Веб-дашборд переведён с Flask на **Litestar 2** (ASGI, uvicorn). Все 13 эндпоинтов сохранены с тем же API (пути и формат ответов не изменились).
- setup.py: зависимость Flask>=2.2 заменена на litestar>=2,<3 + uvicorn>=0.30.
- Статика раздаётся через StaticFilesConfig (Litestar), главная страница отдаётся с text/html.
- index.html не менялся — клиент полностью совместим.
- HTTP-клиент `requests` заменён на `httpx` (запросы к Chrome DevTools: PUT /json/new, GET /json, PUT /json/close).



## [2.0.0] - 2026-06-29

### Форк (29-06-2026)
Независимый форк проекта [parser-2gis](https://github.com/interlark/parser-2gis)
(© Andy Trofimov, LGPLv3).

#### Изменено
- Миграция на `pydantic` v2 (валидаторы, сериализация, `model_config`).
- Объявлена поддержка Python 3.12/3.13; обновлены `pyinstaller`, `pytest`, `tox`, `wheel`.
- Упаковка через `find_packages` (включает все подпакеты).
- Дистрибутив переименован в `parser-2gis-new` (import-пакет `parser_2gis`),
  добавлена консольная команда `parser-2gis-new`.
- Веб-интерфейс стал единственным UI и запускается по умолчанию; `Flask` —
  основная зависимость.

#### Удалено
- Десктоп-GUI (tkinter/`PySimpleGUI`/`FreeSimpleGUI`) и зависимость от него —
  все функции перенесены в веб.

#### Исправлено
- Парсинг в headless-режиме возвращал 0 записей с ошибкой 2GIS API
  `«Bound is incorrect»`: карта (WebGL) не инициализировалась, страница отправляла
  вырождённый viewport (`viewpoint1 == viewpoint2`). Исправлено новым headless-режимом
  Chrome (`--headless=new`) и принудительным размером вьюпорта вкладки.

#### Добавлено
- Веб-интерфейс — локальный дашборд: направления, фильтры, запуск/стоп, живой
  прогресс, карточки результатов с кнопками WhatsApp/звонок/2GIS/соцсети и экспорт.
- Генератор ссылок в вебе: страна + города (мультивыбор) + рубрика (поиск) →
  готовые URL 2GIS добавляются в список направлений.
- Расширенные настройки в вебе: лимит RAM, задержка кликов, «точные совпадения»,
  кодировка, CSV-опции (рубрики, комментарии, пустые колонки, дубликаты, колонок на поле).
- Фильтры результатов (для всех форматов): без франшиз (дедуп по организации),
  только с телефоном / WhatsApp / соцсетями / e-mail / сайтом, по рейтингу и отзывам.
  Доступны в CLI (`--filters.*`) и в вебе.
- Чистый режим CSV/XLSX (`--writer.csv.clean`) — только основные читаемые колонки.
- Новый формат `html` (`-f html`) — страница с карточками и кнопками WhatsApp / звонок /
  2GIS / соцсети и живым поиском.
- Улучшенный XLSX — кликабельные ссылки, авто-ширина колонок, заморозка шапки, автофильтр.
